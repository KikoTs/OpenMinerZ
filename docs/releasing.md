# Prepare a public release

Public packages contain OpenMinerZ code/binaries, approved example media and
their notices. Each player imports original game assets locally. Never publish
the local `play.bat` directory, a content pack, a Rig Lab export or an old private
playtest archive.

## Review the source

```powershell
py -3 tools/release.py --history
py -3 -m unittest discover -s tools/tests -p 'test_*.py'
```

The audit includes tracked and untracked non-ignored source files. It rejects
proprietary formats, import markers, build output, local agent folders,
credential patterns, changed/unapproved media and broken Markdown links.
`--history` additionally checks historical Git object paths for forbidden files;
it does not rewrite history. A passing scan is a technical check, not proof of
copyright ownership or a comprehensive secret audit. Review the diff and media
provenance before uploading.

`tools/release-assets.json` lists each approved media file's origin, license and
SHA-256. Update it only after examining the changed asset and its authoring source
or license. Original example art is generated by `tools/ModSdk`; recorded foley
uses separately credited CC0/CC BY sources. Player animation packs must not
contain original reference clips, meshes, skins or imported rest-pose offsets.

## Source archive

```powershell
py -3 tools/release.py --history --source-zip out/releases/OpenMinerZ-source.zip
```

The archive includes the audited working files, including uncommitted changes,
and records their fingerprint. It excludes `.git`, ignored files, captures,
builds and imports. Existing archive names are refused. Keep the checksum beside
the archive. Review and commit the release changes before creating a tag.

## Windows runtime package

From a VS developer PowerShell with the prerequisites in [building.md](building.md):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/Package-Release.ps1 `
  -PackageName OpenMinerZ-0.1.0-preview
```

This uses `native-public`, an independent build with owned imports and game paths
disabled. It builds and tests, checks source stability, and assembles an explicit
file list: native game/SDK, our Steam/audio/import helpers, open-source runtime
dependencies, approved examples, importer/launcher scripts and license notices.
It excludes original assets, Steam DLLs, Microsoft installers, saves and profiles.

A matching source ZIP is produced beside the runtime ZIP. Distribute both with
their SHA-256 files. Include the source archive with every binary distribution;
do not substitute a source link that omits local changes used to build it.
AGPL-3.0-or-later also addresses modified software used over a network; read
[LICENSE](../LICENSE) for the applicable terms. Third-party licenses remain separate.
The default output is `out/releases/`; older private playtest folders are not
public packages and must not be uploaded.

## Manual release checks

- Import from an owned installation into an isolated private destination.
- Start from a fresh user profile and confirm setup errors are understandable.
- Test creating, saving and loading a world; inspect important visual/audio changes.
- Validate bundled add-ons and test the intended multiplayer combinations with
  consenting testers. Record limitations honestly in the release notes.
- Inspect archive contents and notices. Imported assets must not be present.
- Publish the reviewed commit/tag and corresponding artifacts only when ready.

The cleanup/build scripts do not push commits, publish releases, change repository
visibility or delete Git history. Retained private backups and captures belong
outside the public repository and must not be uploaded with it.
