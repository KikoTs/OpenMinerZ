# Author an add-on

Build `openminerz_mod_sdk` using the [build guide](../building.md). The SDK uses
the same API registry, validation and simulation services as the game.

## Create and run

```powershell
$sdk = '.\out\build\native-release\Release\openminerz_mod_sdk.exe'
& $sdk new mymod --template server --dir "$env:LOCALAPPDATA\OpenMinerZ\Mods"
$mod = "$env:LOCALAPPDATA\OpenMinerZ\Mods\mymod"
& $sdk validate --strict $mod
& $sdk run $mod --seconds 10 --chat '/hello'
```

Add this to the generated `server/main.luau` before using `/hello`:

```luau server
commands.register("hello", "Greet the player", function(player)
    return "Hello, " .. players.get(player).name
end)
```

The runner creates a flat test world with server and client VMs and a test player.
It does not validate visual quality, graphics-driver behavior or a real Steam
session. Launch the game and check the actual feature after the headless test.

## Files and scope

Keep the manifest generated by `new` as your starting point. Its `id`, `version`,
API requirement, `scope`, `protocol`, description and optional dependencies/
conflicts are validated. Use `--template client` for a presentation-only pack.

| Folder | Role |
| --- | --- |
| `shared/` | Definitions used on both sides; guarded side-specific code only |
| `server/` | World, inventory, damage, creature and persistence authority |
| `client/` | UI, graphics, sound, input and client network messages |
| `assets/` | Original or licensed media; paths are local to the add-on |
| `lang/` | Translation files |

```luau shared
log.info(mod.id(), mod.version(), "loaded on", mod.side())
if mod.has("camera.shake") then
    camera.shake(0.1, 0.2)
end
```

`shared/` runs in two VMs. Do not run server operations there unconditionally.
Use `mod.side()`/`mod.has()` when needed. The sandbox does not provide arbitrary
filesystem, process or network access. Use the registered APIs, `storage.*` and
schema-checked `net.*` messages.

Names defined by a mod are namespaced: a local `canteen` in `mymod` is
`mymod:canteen` to other mods. Declare dependencies before accessing their modules
or content. Use relative `require("./lib/util")` paths for your own modules.
Handles have a kind and ID; use the API to inspect them and tolerate removed
players/entities instead of treating a cached handle as permanent.

## Presentation-only example

This belongs in a client-scoped add-on's `client/main.luau`:

```luau client-mod
ui.theme({colors = {
    ["menu.focus"] = "#ffb040",
    ["menu.heading"] = "#ffd890",
    ["hud.band"] = "#ff9030",
}})
```

Presentation must not grant damage, inventory, aim or terrain authority. Put
gameplay changes in a server-scoped add-on instead of trying to work around
missing client capabilities.

## Assets and larger features

Use the [API reference](api-reference.md) for exact field names and limits.
The complete examples are the reference implementations for related features:

| Feature | Example/source |
| --- | --- |
| Items, recipes, hunger, liquids | `examples/mods/survival`, `examples/mods/wilderness` |
| NPCs, quests and structures | `examples/mods/story_dungeon` |
| Creature brains, senses, attacks, boss phases | `examples/mods/bestiary` |
| Biomes, caves, ores and deterministic terrain | `examples/mods/frontier`, `examples/mods/wilderness` |
| HUD widgets, menus, fonts and images | `examples/mods/ui_theme` |
| Lights, model props, atmosphere, LUTs and sound | `examples/mods/lighting_pack` |
| Animation and weapon motion | [animation.md](animation.md) |

Graphics paths commonly omit the `assets/` prefix and extension (for example
`models/fox` or `sounds/bell`); UI file paths can require the full asset path.
Follow the relevant API entry. glTF models use their own local assets. Keep image,
audio and model files inside the pack; external paths and executable files are
not accepted. `retail:` model references resolve to the player's local imports
and do not require copying the original model into your add-on.

Do not ship exported rigs, original animation reference clips, copied gun meshes,
game textures or audio banks. Keep the credits for licensed recordings and art.

### Held items

For a custom held model, use metres, with the origin where the fist closes
around the grip. +Y points up the blade or handle and +Z is the face shown to
the holder; X spans the guard or blade edges. The Wilderness broadsword and club
and `tools/ModSdk/make_wilderness_weapons.py` demonstrate this convention.
Check the model in first and third person. A mesh that looks correct in a viewer
can still have an incorrect grip origin or orientation in the game.

Item-model clips such as `idle`, `equip` and `use` animate your model. Player
bone animation uses the separate [animation-pack workflow](animation.md).

## Test and debug

```powershell
& $sdk validate --strict $mod
& $sdk validate --types $mod
& $sdk run $mod --seconds 60
& $sdk run $mod --seconds 60 --classic
& $sdk digest $mod
```

`validate` checks syntax, API use, capabilities, descriptors, requires, assets
and registered content. `--types` adds Luau type analysis. Console errors name
the file, line, mod ID and VM side. Use `log.info`, `log.warn` or `log.error`.
`/mods reload` preserves API-managed storage; restart an online host after edits.

For editor completion use `tools/ModSdk/types/openminerz.d.luau`. The adjacent
JSON describes the same API for other tools and coding agents. Keep editor
configuration above your mod folder rather than putting arbitrary tool files
inside the distributed pack.

## Publish

Increment the version after changing content. Test each protocol you declare.

```powershell
& $sdk validate --strict $mod
& $sdk pack $mod --out "$PWD\out\addon-releases"
```

`pack` validates and writes a versioned folder with digests and install steps.
Archive that folder, not your development directory. Include a short README.txt,
license and required third-party credits. Players extract the add-on folder into
their Mods directory; the game does not load the ZIP directly. Engine releases
use the separate [public packaging workflow](../releasing.md).
